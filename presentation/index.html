04 // Security & Resilience

4-Tier Resilient Authentication Engine

Seamless token acquisition that works out-of-the-box in local development, CI/CD, and BTP production.

Tier 1: Direct Bearer Token Fastest

Uses `CF_BEARER_TOKEN` directly from `default.env` or system environment for instant API access.

Tier 2: User Password OAuth Grant Interactive

Automated POST to `/oauth/token` with `grant_type=password` and handles lockouts gracefully.

Tier 3: OAuth Client Credentials Production

Standard service-to-service BTP authentication utilizing XSUAA binding credentials.

Tier 4: Local CF CLI Session Bridge Zero-Config

Executes `cf oauth-token` on the developer workstation to inherit active terminal credentials.

srv/incidents.ts (Auth Hierarchy) 
// 4. Fallback to active local CF CLI session
try {
    LOG.info('Attempting fallback to local CF CLI...');
    const cliToken = execSync('cf oauth-token', {
        encoding: 'utf8',
        stdio: ['ignore', 'pipe', 'ignore']
    }).trim();

    if (cliToken && cliToken.startsWith('bearer ')) {
        LOG.info('Retrieved active OAuth token from CF CLI!');
        return cliToken;
    }
} catch (cliErr) {
    LOG.warn('Local CF CLI token fallback not available');
}
05 // Data Modeling

Normalized Telemetry Domain Model

Rich CDS data model in `db/schema.cds` capturing relational incident structures with composition cascading.

db/schema.cds 
namespace shubh.incidents;
using { cuid, managed } from '@sap/cds/common';

entity Incidents : cuid, managed {
    targetSpace         : String(100);
    correlatedRequestId : String(100);
    status              : String(20) default 'OPEN';
    errorCategory       : String(50);
    rootCauseStatement  : LargeString;
    remediationAction   : LargeString;
    impactedServices    : Composition of many ImpactedServices;
    traces              : Composition of many TraceEvents;
    messages            : Composition of many Messages;
}

ImpactedServices

Maintains 1:N relations to target microservices, container instance GUIDs, and binding relationships.

TraceEvents

Timestamped log records tracking router (`RTR`), cell manager (`CELL`), and app runtime (`APP`) status codes and levels.

Messages

Audit log updates, operator annotations, and AI agent diagnostic summaries appended chronologically.

06 // Ingestion Engine

Automated CF Telemetry Synchronization

Event-driven and query-triggered ingestion keeping incident telemetry perpetually fresh.

The Ingestion Pipeline

01
Lifecycle Interception: CAP `before('READ', 'Incidents')` triggers transparently before query execution.
02
Cloud Controller Query: Fetches `/v3/apps` and `/v3/audit_events` in parallel using active OAuth headers.
03
Heuristic Normalization: Maps status codes (`CRASHED` -> 503, `STARTED` -> 200, `audit.event` -> status/criticality).
04
Idempotent Upsert: Executes `UPSERT.into(Incidents)` to update records without duplicating entries.
srv/incidents.ts (Event Normalization) 
// Normalizing Cloud Foundry Audit Events
let logLevel = 'INFO';
let status = 'OPEN';

if (eventType.includes('delete') || eventType.includes('crash')) {
    logLevel = 'ERROR';
    status = 'INVESTIGATING';
} else if (eventType.includes('update')) {
    logLevel = 'WARN';
}

await cds.tx(req).run(
    UPSERT.into(Incidents).entries(incidentRecord)
);
07 // AI Protocol

Model Context Protocol (MCP) Integration

Exposing SAP CAP services as standard tool definitions for LLMs and AI Agents.

package.json (MCP Configuration) 
"cds": {
  "mcp": {
    "name": "cf-log-trace-agent-mcp",
    "wrap_entities_to_actions": true,
    "wrap_entity_modes": [
      "query", "get", "create", "update", "delete"
    ],
    "instructions": "MCP Server for Cloud Foundry Log & Trace Incident Agent. Enables querying, updating, and remediating incidents."
  }
}

Auto-Generated AI Toolset

The CAP runtime exposes these tools at http://localhost:4004/mcp:

🛠️ incidents_query: Filter & inspect incidents
🛠️ traceEvents_query: Drill down into RTR & CELL logs
🛠️ impactedServices_query: Identify failing microservice pods
🛠️ incidents_update: Update root cause & remediation actions
08 // Agent In Action

Autonomous SRE Incident Remediation

How Claude, Gemini, or custom Antigravity agents diagnose issues without human bottleneck.

STEP 01
🔍

Detect

Agent queries `/mcp` tools; discovers an incident with status INVESTIGATING and error CF_APP_STATUS.

STEP 02
🔬

Correlate

Agent calls traceEvents_query filtering by correlated request ID to extract router 503 traces.

STEP 03
💡

Analyze

Agent links crash to a memory quota exhaustion or unmapped route based on audit logs.

STEP 04
🛡️

Remediate

Agent updates remediationAction, logs diagnostic notes to messages, and alerts the SRE team.

Agent Prompt Example: JSON-RPC Tool Call
"Call tool incidents_update with ID: 'cf-app-guid-101', status: 'RESOLVED', remediationAction: 'Scaled container memory to 1024M via CF CLI'."
